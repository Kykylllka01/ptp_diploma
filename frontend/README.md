# Тестовый фронт: банк вопросов и тестирование (ТюмГУ)

Кликабельная версия прототипа из 12 экранов на чистых HTML, CSS и JS. Бэкенда нет: все данные лежат в `assets/js/mock-data.js`, а действия пользователя (одобрил вопрос, подтвердил оценку, прошёл тест) сохраняются в `localStorage` браузера, поэтому видны на соседних экранах.

## Как открыть

Двойной клик по `index.html`, сборка и сервер не нужны. Если браузер что-то блокирует при открытии файла напрямую, запустите в этой папке любой статический сервер, например `npx serve .` или `python -m http.server`, и откройте `http://localhost:3000` (или `:8000`).

Кнопка «Сбросить демо-данные» на `index.html` возвращает всё к исходному состоянию.

## Структура

```
frontend/
├── index.html                  список всех экранов
├── teacher/                    экраны преподавателя (1–8)
│   ├── dashboard.html          1. Обзор
│   ├── upload.html             2. Загрузка материалов и параметры
│   ├── pipeline.html           3. Работа агентов
│   ├── bank.html               4. Банк вопросов
│   ├── question.html?id=Q-121  5. Проверка и редактирование вопроса
│   ├── test-builder.html       6. Сборка теста
│   ├── analytics.html          7. Результаты и аналитика
│   └── review.html             8. Проверка открытых ответов
├── student/                    экраны студента (9–12)
│   ├── tests.html              9. Мои тесты
│   ├── test.html               10–11. Прохождение теста (все типы вопросов)
│   └── result.html             12. Результат и разбор
└── assets/
    ├── css/app.css             все стили, цвета ТюмГУ в переменных :root
    ├── img/logo.png
    └── js/
        ├── mock-data.js        моковые данные (будущие таблицы и ответы API)
        ├── app.js              шапка, хранилище, помощники
        ├── grading.js          подсчёт баллов попытки (будущая логика сервера)
        └── pages/*.js          код отдельных экранов
```

Экраны 10 и 11 из прототипа объединены в один `student/test.html`: тип вопроса (варианты, несколько верных, SQL, развёрнутый) определяется данными, как и будет в реальном тесте. `student/test.html?mode=training` открывает режим тренировки без таймера и с подсказками.

## Перенос в Laravel

Стек: Laravel как единственный бэкенд, Node.js только для сборки фронта через Vite.

| Сейчас | В Laravel |
|---|---|
| `assets/css/app.css` | `resources/css/app.css`, подключается через `@vite` |
| `assets/js/app.js`, `grading.js`, `pages/*.js` | `resources/js/...`, точка входа `resources/js/app.js` |
| `assets/img/logo.png` | `public/images/logo.png` |
| `<header data-layout="teacher">`, который рисует `app.js` | `resources/views/layouts/teacher.blade.php` и `student.blade.php` с `@yield('content')` |
| `teacher/*.html`, `student/*.html` | `resources/views/teacher/*.blade.php`, `student/*.blade.php`, маршруты в `routes/web.php` |
| `mock-data.js` | модели и миграции (`materials`, `questions`, `tests`, `attempts`, `answers`, `reviews`) и API в `routes/api.php` |
| `App.store` (localStorage) | запросы `fetch('/api/...')` или данные из контроллера в Blade |
| имитация в `pipeline.js` | очереди Laravel (jobs) для агентов, статус через polling или Laravel Echo |
| `grading.js` | сервис оценки на сервере: варианты сразу, SQL на учебной базе, развёрнутые ответы через агента-оценщика |

Порядок переноса: сначала layout и статичные экраны в Blade, затем модели с сидерами из `mock-data.js`, затем по одному экрану заменять моковые данные на реальные.

## Что здесь не настоящее

- Генерация вопросов, работа агентов и проверка развёрнутых ответов. Оценка открытого ответа в `grading.js` считается по ключевым словам, только для демонстрации.
- «Выполнить на учебной базе» возвращает заготовленную таблицу.
- Загрузка файлов, OCR, экспорт (в аналитике выгружается CSV с моковыми данными), публикация теста.
