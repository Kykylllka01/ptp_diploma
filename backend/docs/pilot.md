# Пилот: 200 студентов, несколько групп и преподавателей

Регламент для администратора и преподавателей. Что сделано в коде для пилота — в PR #28–#31.

## За неделю: настройки сервера

1. **Обновить код и базу:**
   ```
   git pull
   php artisan migrate --force
   ```
   Затем пересобрать фронтенд:
   ```
   node --max-old-space-size=512 node_modules/vite/bin/vite.js build
   ```
2. **`.env`:**
   - `APP_ENV=production`, `APP_DEBUG=false` — иначе при ошибке студент увидит трассировку;
   - `LOG_STACK=daily` — журнал по дням, а не один растущий файл;
   - `QUEUE_CONNECTION=database`, `QUEUE_AUTOSTART_PHP=<путь к php.exe>`;
   - `QUEUE_MAX_WORKERS=3` — сколько ответов оценивается параллельно;
   - `SQL_SANDBOX_PARALLEL=6` — сколько SQL-запросов студентов выполняется одновременно.

   После правки выполнить `php artisan config:clear`.
3. **MySQL** (`OSPanel6\config\MySQL-8.4\default\templates\my.ini`): `max_connections = 200`. Сейчас стоит 128 — это столько же, сколько потоков Apache (`ThreadsPerChild 128`). Ещё нужны соединения для обработчиков очереди и планировщика, поэтому при общей сдаче возможна ошибка «Too many connections». После правки перезапустить модуль MySQL.
4. **Планировщик:** задача OSPanel `.osp/tasks.ini` раз в минуту запускает `php artisan schedule:run`. Он досдаёт брошенные попытки и будит очередь. После изменения задач перезапустить панель.
5. **Администратор и преподаватели.** Администратор создаётся только из консоли, команда печатает временный пароль один раз:
   ```
   php artisan admin:create почта "Фамилия Имя Отчество"
   ```
   Администратор входит на сайт и попадает в админ-панель `/admin`:
   - создаёт ссылку-приглашение — одноразовую или на 5–30 человек, на 1–30 дней — и отправляет её преподавателю; тот регистрируется сам и сразу попадает в кабинет преподавателя;
   - отзывает ссылку, если она ушла не туда;
   - выдаёт преподавателю новый пароль;
   - закрывает и возвращает доступ: материалы и тесты преподавателя при этом остаются на курсе.

   Без админ-панели преподавателя можно завести и из консоли: `php artisan teacher:create почта "Фамилия Имя Отчество"`.
6. **Проверка готовности:** `php artisan pilot:check`. Ошибок (FAIL) быть не должно. Предупреждения (WARN) — по таблице выше.

## За 2–3 дня: группы и тесты

- Каждый преподаватель создаёт на странице «Группы» свои группы и рассылает студентам ссылки-приглашения. Когда все зарегистрировались, регистрацию закрывают: тогда ссылку нельзя переслать посторонним.
- **Тест собирается для конкретных групп.** Если групп несколько, сборка не даст опубликовать тест, пока группы не отмечены. «Все студенты курса» выбирается только явно.
- **Банк вопросов общий.** По умолчанию каждый видит свои материалы, вопросы и тесты; чужие — через «Все преподаватели». Удалить запись может только её автор.
- Перед пилотом каждый проходит свой тест сам: «Тесты → ⋯ → Пройти самому».
- **Резервная копия базы:**
  ```
  mysqldump -u root ptp_diploma > ptp_diploma-<дата>.sql
  ```

## В день тестирования

- **Вход:** вся группа входит с одного Wi-Fi. Лимиты считаются по почте, а не по IP, поэтому массовый вход не блокируется. Подбор пароля к одной почте ограничен 10 попытками в минуту.
- **Сохранение ответов:** ответы сохраняются автоматически. Если связь пропала, в панели справа написано «не сохранено». Ответы повторно отправляются каждые 5 секунд — страницу закрывать не нужно.
- **Конец времени:** сдачи автоматически разносятся на 0–15 секунд, чтобы сервер не получил все разом. Если сдача не прошла, браузер повторяет её сам до 5 раз. Брошенные попытки досдаёт планировщик с уже сохранёнными ответами.
- **Развёрнутые ответы** оценивает агент в фоне, до трёх параллельно. Сотни ответов после общей сдачи разбираются за десятки минут. Студент сразу видит предварительный результат.
- **Жёсткий прокторинг:** уходы со страницы видны преподавателю в ответах студента, в аналитике теста и в журнале.
- **Наблюдение:** `php artisan pilot:check` — упавшие и зависшие задачи. Журнал ошибок — `storage/logs`.

## Если что-то пошло не так

| Что видно | Что делать |
|---|---|
| Развёрнутые ответы долго «оцениваются» | `pilot:check` → «Зависшие задачи». Запустить вручную: `php artisan queue:work --stop-when-empty --timeout=1800` |
| Агент недоступен (нет ключа, сеть) | Ответы всё равно попадают в «Проверку ответов» без подсказки агента — их оценивает преподаватель |
| «Учебная база сейчас перегружена» при сдаче | Сдача откатывается, ответы сохранены — студент нажимает «Завершить тест» ещё раз (по окончании времени браузер повторяет сам) |
| Студент забыл пароль | «Группы» → студент → «Выдать новый пароль» |
| Тест открыт не той группе | «Тесты» → «⋯» → «Срок, группы и прокторинг» |
