# Выпуск версии и выкладка на хостинг

На хостинг попадают только выпущенные версии: у каждой есть номер, тег `vX.Y.Z` в git,
запись в [CHANGELOG.md](../../CHANGELOG.md) и страница на GitHub (Releases).

## Номер версии

`МАЖОРНАЯ.МИНОРНАЯ.ПАТЧ`, например 1.2.3:

| Что изменилось | Какую цифру увеличить | Пример |
|---|---|---|
| Только исправления | ПАТЧ | 1.0.0 → 1.0.1 |
| Новая возможность, старое работает как раньше | МИНОРНАЯ, ПАТЧ — в 0 | 1.0.3 → 1.1.0 |
| Нужно что-то сделать вручную: настроить сервер, переучить преподавателей | МАЖОРНАЯ, остальные — в 0 | 1.4.2 → 2.0.0 |

Номер записан в `backend/VERSION`; на сервере его показывает первая строка `php artisan pilot:check`.

## Каждый PR

В том же PR — строка в раздел **«Не выпущено»** в `CHANGELOG.md`, в подраздел «Добавлено», «Изменено» или
«Исправлено». Писать для преподавателя, а не для программиста: что стало по-другому и зачем, со ссылкой на PR.

## Выпуск

1. Ветка `release/vX.Y.Z` от свежего `main`:
   - в `CHANGELOG.md` раздел «Не выпущено» становится `## [X.Y.Z] — ГГГГ-ММ-ДД`, над ним — новый пустой «Не выпущено»;
     внизу — ссылка `[X.Y.Z]: …/releases/tag/vX.Y.Z` и `[Не выпущено]: …/compare/vX.Y.Z...HEAD`;
   - в `backend/VERSION` — новый номер.
2. PR «Выпуск X.Y.Z», тесты, слияние в `main`.
3. Тег и страница выпуска на GitHub:
   ```bash
   git checkout main && git pull
   git tag -a vX.Y.Z -m "Версия X.Y.Z"
   git push origin vX.Y.Z
   awk '/^## \[X.Y.Z\]/{f=1;next} /^## /{f=0} f' CHANGELOG.md > notes.md
   gh release create vX.Y.Z --title "X.Y.Z" --notes-file notes.md && rm notes.md
   ```
   После `git checkout` проверить, что `backend` по-прежнему ссылка (junction) на папку OSPanel.

## Выкладка

Не во время теста у студентов: миграции и перезапуск обработчиков идут на работающем сайте.

```bash
scripts/deploy.sh vX.Y.Z
```

Скрипт проверяет, что рабочая копия стоит на выпуске и `backend/VERSION` совпадает с тегом, собирает фронтенд,
загружает код выпуска, ставит зависимости, выполняет миграции, обновляет кэш настроек, перезапускает обработчики
очереди и запускает `pilot:check`. Адрес сервера и ключ — в `scripts/deploy.env` (не в git, образец —
`scripts/deploy.env.example`). Перед выпуском с миграциями, меняющими данные, — копия базы: на сервере
`~/ptp-backup/backup.sh`.

## Откат

Выложить предыдущую версию: `git checkout vX.Y.(Z-1)`, `scripts/deploy.sh vX.Y.(Z-1)`, затем `git checkout main`
(и проверить junction `backend`). Миграции при этом назад не откатываются — если новая версия меняла базу,
восстановить копию из `~/ptp-backup/db`.
